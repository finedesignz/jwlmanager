<objective>
Bind `jwlCore` from `libs/` via `libloading` with arch-aware `(OS, ARCH)` selection (fixing the Python bridge's arch-blind bug), resolve its symbols and read its version — load + resolve only, no merge call (D-12). Expose it as a lazy `check_jwlcore()` command so a missing/wrong-arch binary is a UI error state, not a startup crash.

Purpose: jwlCore loading is one of the three riskiest integrations the phase goal names; the arch-aware fix (D-13) is genuinely load-bearing now that Windows ships a native arm64 build (D-13a).
Output: `jwlcore/loader.rs`, the `check_jwlcore` command, bundled `libs/*` resources, and per-target selection tests including the arm64-windows typed no-binary error.
</objective>
