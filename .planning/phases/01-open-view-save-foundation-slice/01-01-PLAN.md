<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| file -> Rust core | An opened `.jwlibrary` is untrusted input (may be crafted); crosses into extraction/parse |
| webview (JS) -> Tauri IPC | Frontend command args (paths) cross into the trusted backend |
| package registries -> build | crates.io / npm dependencies enter the trusted build |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | archive/extract.rs | mitigate | `zip` >=2.3.0 `extract` with enclosed_name validation; full zip-slip fixture + rejection test lands in Plan 02 |
| T-01-02 | Tampering | archive/manifest.rs check_validity | mitigate | Strict serde struct parse (parse failure = reject); no loose `.get().unwrap_or(0)` reads |
| T-01-03 | Information Disclosure | tests/fixtures.rs | mitigate | Synthetic-only fixtures (D-06); repo-scan test asserts no `.jwlibrary` tracked (GDPR Art. 9) |
| T-01-04 | Denial of Service | open_archive command | mitigate | Typed errors + no `unwrap`/`expect` (clippy `-D warnings`); malformed input cannot panic the app |
| T-01-05 | Tampering | webview path arg | mitigate | Path selection via Tauri native file dialog, not arbitrary JS strings; narrow tauri.conf capabilities |
| T-01-SC | Tampering | cargo/npm installs | mitigate | Verify each package version on registry before pinning; all named deps are long-established (no `[SLOP]`/`[SUS]`) |
</threat_model>
