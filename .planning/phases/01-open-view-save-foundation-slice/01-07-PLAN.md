<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| file -> Rust core | An opened `.jwlibrary` is untrusted input (may be crafted); crosses into extraction/parse |
| webview (JS) -> Tauri IPC | Frontend command args (paths) cross into the trusted backend |
| Rust core -> webview | Only sanitized `ErrorDto` (no raw paths / source internals) crosses back out |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | archive/extract.rs | mitigate | Exact-pinned `zip` `extract` with enclosed_name validation; a `../` entry is refused (full 6-variant zip-slip fixture + rejection test lands in 01-02) |
| T-07-02 | Tampering | archive/mod.rs v16-only validity | mitigate | Typed rejections on missing manifest/userDataBackup; schemaVersion != 16 rejected as UnsupportedSchema (no unsafe open of un-upgraded v12-15); no loose `.get().unwrap_or(0)` reads |
| T-07-03 | Information Disclosure | ErrorDto boundary | mitigate | Internal ArchiveError (wraps io/rusqlite/path Display) never crosses IPC; only ErrorDto (code + message_key + base file name) does — no path/SQL leakage (SAFE-05) |
| T-07-04 | Denial of Service | open_archive command | mitigate | Typed errors + no `unwrap`/`expect` (clippy `-D warnings`); malformed input cannot panic the app |
| T-07-05 | Tampering | webview path arg | mitigate | Path selection via Tauri native file dialog, not arbitrary JS strings; narrow tauri.conf capabilities (declared in 01-01) |
</threat_model>
