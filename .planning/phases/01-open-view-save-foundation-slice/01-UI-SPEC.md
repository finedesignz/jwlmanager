# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope guard:** This phase's UI surface is a Walking Skeleton only — open/save/save-as/new command surface, a single virtualized Notes list, an error surface, and a jwlCore-capability notice. The other five category views (DATA-02..06), editing UI, dry-run preview, merge UI, and settings/theme-switcher are explicitly deferred to later phases (6, 7, 2, 5, 11) and are NOT specified here.

## Spacing Scale

Declared values (must be multiples of 4), per `~/.claude/design-preferences.md`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (toolbar icon gaps) |
| md | 16px | Default element spacing, list row horizontal padding |
| lg | 24px | Section padding (app shell margins) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks (not used at this phase's scale) |
| 3xl | 64px | Page-level spacing (not used at this phase's scale) |

Exceptions:
- **Notes list row height: fixed 44px** (touch-target floor per global design-preferences, and the number TanStack Virtual's `estimateSize` must return — a hard perf-relevant constant, not a spacing-scale token. Do not vary row height per row; DATA-01's 9,000-row virtualization story depends on uniform row height for a cheap `estimateSize`).
- **Toolbar/command-bar icon buttons: 44×44px hit area** (16–18px Lucide glyph in ~14px padding) — same global rule as row height, applied to Open/New/Save/Save As actions.

## Typography

Declared per global design-preferences.md defaults (`text-sm`/`text-xs` scale), applied to this phase's two real surfaces (Notes list rows, toolbar/error banner):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.4 |
| Heading | 16px | 600 (semibold) | 1.2 |
| Display | 20px | 600 (semibold) | 1.2 |

`[auto] Typography — Q: "3-4 sizes, 2 weights?" → Selected: 14/12/16/20px, weights 400+600 (recommended default, matches global design-preferences card-heading/caption scale).`
**Rationale:** This phase has no marketing surface and no large display moments — the "Display" role (20px) is reserved for the empty-state heading and the toolbar's window/app title area only. Body (14px) carries every Notes-row cell and the error banner message. Two weights only: 400 for all data/body text, 600 for headings/labels-that-need-emphasis (column headers, error banner title, empty-state heading).

## Color

Dark-first per global design-preferences (`--bg-primary`/`--bg-secondary`/`--bg-tertiary` token triad), token-based, no raw hex in component code — hex values below exist only to seed the CSS variables.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1a1a1a` (`--bg-primary`) | App shell background, Notes-list viewport background |
| Secondary (30%) | `#242424` (`--bg-secondary`) | Toolbar/command-bar surface, alternating list-row tint, error banner card |
| Accent (10%) | `#2563eb` blue-600 (`--brand-primary`) | Focus rings, active/selected list row, primary toolbar icon-button hover state, jwlCore-capability info icon |
| Destructive | `#dc2626` red-600 | Error banner icon/border, zip-slip rejection message, "no binary for this platform" is explicitly NOT this color (see Copywriting) |

`[auto] Color — Q: "Which cool-primary accent?" → Selected: blue-600 (recommended default per global design-preferences "internal app accent: blue or green, pick ONE").`
**Rationale:** The existing Python app's `dark.qss` uses orange (`#d97917`) as its selection/highlight color throughout (`selection-background-color`, `QMenuBar::item:selected`, progress-bar chunk). Global design-preferences explicitly reserves orange for CTA/pop-accent only and bans it as an app accent (`--brand-primary`) for internal tools — "Never indigo... Orange is NOT an app accent." Blue is chosen over green because it reads as more neutral/trustworthy for a data-integrity tool (Core Value: "never lose or corrupt"), avoiding the "success/save" connotation green carries, which would be misleading on a tool where most user actions are read-only in this phase. This is a deliberate visual break from the Python app's orange, not an oversight — noted here so the checker doesn't flag it as an unexplained inconsistency.

Accent reserved for: focus ring (every interactive element per accessibility baseline), the selected/active Notes row's left border + subtle background tint, the "i" info icon that reveals jwlCore capability detail (per global tooltip convention), and hover state on toolbar icon buttons (Open/New/Save/Save As). **Not** used for the error banner (destructive red) or for body text.

## Copywriting Contract

Voice per global design-preferences: direct, technical, plain, no exclamation points, no "Oops."

| Element | Copy |
|---------|------|
| Primary CTA | **"Open Archive"** — toolbar button/menu item that triggers the native file-open dialog. (Save/Save As/New are secondary toolbar actions, not the phase's single primary CTA — the phase's first meaningful action is opening a file.) |
| Empty state heading | **"No archive open"** |
| Empty state body | **"Open a `.jwlibrary` file to view your Notes, or create a new archive."** + two inline actions: "Open Archive" (primary) and "New Archive" (secondary/ghost) — per global empty-state rule: one sentence, primary CTA, no paragraph. |
| Error state (archive open/save failure) | **"Couldn't open this archive — {typed-error detail from Rust, e.g. 'the file isn't a valid .jwlibrary backup'}. Choose a different file or check that it hasn't been moved."** Pattern: what happened (verb-led) + why (typed error) + what to do next. Every `thiserror` variant surfaced to the frontend (D-14) must map to a specific sentence in this pattern — never a bare error code or raw Rust `Display` string. |
| Error state (zip-slip rejected) | **"This archive can't be opened — it contains files that try to write outside the extraction folder, which isn't safe. This file may be corrupted or tampered with."** Distinct from a generic open failure: this is a security rejection, not a format problem, and the copy says so plainly without alarming ALL-CAPS or exclamation points. |
| jwlCore capability notice (informational, NOT an error) | **"Merge isn't available on this device (no jwlCore build exists yet for Windows on Arm). Everything else — opening, viewing, and saving archives — works normally."** Rendered as a muted, dismissible info banner (icon + text, `--text-muted`, no red/destructive styling, no toast) — per D-13a this is expected/known, not a fault. Only shown on the arm64-Windows target where `check_jwlcore()` returns the typed no-binary error; never shown where jwlCore loads successfully. |
| Destructive confirmation | None in this phase — Phase 1 has no destructive operations (delete/merge/downgrade are Phases 2/5/4). Save/Save As/New are non-destructive to the source file per D-03/D-04/D-05 (source is read-only, atomic rename, save-as never mutates the original) and therefore need no confirmation step. |

## Component Inventory (Phase 1 scope only)

| Component | Source | Notes |
|-----------|--------|-------|
| Command bar / toolbar | custom (shadcn `Button` + Lucide icons) | New / Open / Save / Save As — icon+label buttons, not icon-only (only 4 actions, room for labels; global "icon-only in dense rows" rule applies to table rows, not a 4-item top toolbar) |
| Notes list | custom, `@tanstack/react-virtual` | Single flat virtualized list, NOT a full data-table (no sort/resize/hide-column chrome in this phase — that global table-controls convention is deferred to Phase 6 when DATA-07 selection/bulk-actions and multi-category browsing land) |
| Notes list row | custom | Fixed 44px height, single-line: resolved location/publication label (via `resources.db`, per RESEARCH.md Pitfall 3) + truncated note snippet + tag chips (if any) using the standard tag-chip pattern (soft tint + ring + `rounded-full`) |
| Error banner | shadcn `Alert` (or `Toast`/Sonner for transient variants) | Sticky/non-auto-dismiss for real errors (open/save/zip-slip) per global "errors are sticky" rule; the jwlCore capability notice is the one exception — informational, user-dismissible, not sticky-forever |
| Empty state | custom | Centered, muted Lucide icon (e.g. `FileX` or `FolderOpen`), heading + one-sentence body, two CTAs, per global empty-state pattern |

Deferred, not specified this phase: category tabs/switcher (Phase 6), selection checkboxes + bulk action bar (Phase 6/DATA-07), dry-run preview modal (Phase 2), merge dialog (Phase 5), settings/theme toggle (Phase 11), data viewer/editor (Phase 7).
