<objective>
Port `JWLManager.py:3858-3935`'s `trim_db` orphan sweep to Rust as `db/trim.rs`, wire it into the save path (hash-last, D2-04), and land the Wave-0 fixtures + verification that unblock the whole phase. This is the engine that keeps every saved archive internally consistent.

Purpose: ARCH-04 — a save must sweep orphans, re-densify tag positions, set `Location.Title=""` where NULL, and VACUUM, matching the proven Python app semantically (never byte-identical).
Output: `db/trim.rs` (`trim_sweep` + `trim_db`), a `PragmaGuard` RAII helper, a new multi-table-orphan fixture, and `trim_tests.rs`.

**Deliberate deviation from the Python source (documented safety fix):** the Python `trim_db` uses `... NOT IN (SELECT <col> FROM <table>)` over NULLABLE columns (Location, PlaylistItem, and the UserMark/TagMap predicates). A single NULL in the subquery makes `NOT IN` evaluate to UNKNOWN for every row, so genuine orphans are NEVER swept — a latent under-sweep bug. This port replaces every nullable-column `NOT IN` with `NOT EXISTS (SELECT 1 ... WHERE outer.col = inner.col)`, which sweeps correctly. Non-nullable predicates are kept verbatim for order/behavior fidelity. This is intentional and the orphan-swept tests below assert the corrected behavior.
</objective>
