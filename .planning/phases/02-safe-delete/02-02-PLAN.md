<objective>
Build the delete backend: a `NonEmptyNoteIds` newtype that rejects `[]` at the IPC boundary (SAFE-03), a general `DryRunReport` computed inside a rolled-back transaction with SEMANTIC accounting (SAFE-01), parameterized deletes (SAFE-02), transaction rollback (SAFE-04), and the two Tauri commands the frontend will drive. Delete Notes ONLY — `DELETE FROM Note WHERE NoteId IN (...)` and nothing else (matches JWLManager.py:3666); orphans are swept by Plan-01's trim on save (D2-05, corrected).

Purpose: EDIT-01 + the reusable safety net (dry-run / rollback) every later destructive phase inherits.
Output: `db/delete.rs`, two registered commands, and delete/dryrun/roundtrip test files.

**CONTEXT D2-05 correction (state in SUMMARY; executor does not edit CONTEXT):** the current D2-05 wording says delete removes "the Note's UserMark/BlockRange links." That is WRONG and over-deletes — `Note.UserMarkId` is not unique and a UserMark can carry highlight BlockRange data the user did not select. The corrected scope: **delete removes ONLY the selected `Note` rows; trim (Plan 01, with the NOT EXISTS fix) sweeps whatever becomes a genuine orphan on save.** This matches JWLManager.py:3666 exactly (`delete('Note', 'NoteId')` only).
</objective>
