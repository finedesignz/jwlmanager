## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| user intent → destructive apply | the confirm click is the human gate authorizing an irreversible-until-save mutation |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Repudiation / accidental data loss | delete applied without the user seeing what would be removed | mitigate | Dry-run preview with per-table counts shown BEFORE any apply; explicit Confirm required; Cancel is a pure no-op (SAFE-01) |
| T-02-09 | Tampering | empty selection triggering delete from the UI | mitigate | Delete disabled unless `selection.size >= 1` (defense-in-depth); backend `NonEmptyNoteIds` is the enforcement boundary (SAFE-03) |
| T-02-10 | Denial of integrity | double-click firing two concurrent applies | mitigate | Confirm reuses CommandBar's synchronous busy-ref double-click guard — a second click is a no-op |
| T-02-SC | Tampering | npm installs | accept | no new frontend dependencies (uses existing React + generated bindings) |
</threat_model>
