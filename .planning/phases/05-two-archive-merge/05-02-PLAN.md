<objective>
Build the dry-run + commit orchestration on top of Wave 1's FFI wrapper — the direct analogue of
Phase 4's `dry_run_downgrade` + `save_v14_copy` throwaway-copy machinery. The dry-run runs the
REAL merge on a `fs::copy` of the session DB and snapshot-diffs it (jwlCore has no preview mode);
the commit runs it on a staging copy and promotes the result. Expose `merge_dry_run` +
`merge_commit` Tauri commands. RESOLVE the media-blob open question empirically and fold any new
media into `session.entries` so Save never drops merged playlist media.

Purpose: a real, exact merge preview + a safe commit that never corrupts the live session and
never loses media.
Output: `archive/merge.rs`, two Tauri commands, orchestration tests including the media-fold-back.
</objective>

  <action>
  Create `archive/merge.rs`. Define the merge-affected single-PK table set as a `const`
  `MERGE_SNAPSHOT_TABLES: &[(&str,&str)]` of ONLY valid single-i64-PK pairs, mirroring
  `delete.rs::TRACKED_TABLES`: (Note,NoteId), (UserMark,UserMarkId), (BlockRange,BlockRangeId),
  (Bookmark,BookmarkId), (Tag,TagId), (TagMap,TagMapId), (Location,LocationId),
  (PlaylistItem,PlaylistItemId), (PlaylistItemMarker,PlaylistItemMarkerId). MUST NOT include
  InputField or any composite-PK / WITHOUT ROWID table — its key is composite (LocationId,
  TextTag) with no single integer PK, so feeding it to `snapshot_pks` (SELECT {pk_col} — single
  i64) errors at runtime and breaks the dry-run (BLOCKER). Fixed identifiers, never user input.

  Shared internal helper `stage_and_merge(app, session, source_archive, root: &Path) ->
  Result<(), ArchiveError>`: (1) `fs::copy(session.db_path -> root/userData.db)`; (2)
  `extract_zip_slip_safe(source_archive, &root.join("merge"))` (D5-03/D11 zip-slip-safe, source
  READ-ONLY); (3) `jwlcore::merge::run_merge(app, root, &root.join("merge"), false)`.

  `pub fn dry_run_merge(app, session, source_archive) -> Result<DryRunReport, ArchiveError>`:
  make a throwaway dir under `session.temp_dir`; snapshot BEFORE on a fresh copy, then
  `stage_and_merge`, then snapshot AFTER on `root/userData.db` via `snapshot_tables` +
  `diff_snapshots`; best-effort delete the throwaway on EVERY path (mirror save_v14_copy). Do NOT
  trim between merge and the AFTER snapshot (Pitfall 4). Open the copy read-only for snapshots.

  `pub fn merge_commit(app, session: &mut ArchiveSession, source_archive) -> Result<(),
  ArchiveError>`: staging dir under `session.temp_dir`; `stage_and_merge`; on success PROMOTE the merged
  DB ATOMICALLY: reuse `archive::save::atomic_replace` (fs::rename-with-replace) to move
  `staging/userData.db` onto `session.db_path` — NEVER a plain `fs::copy` (a crash mid-copy
  truncates the live working copy = unrecoverable data loss, Core Value violation). Both paths
  live under `session.temp_dir` (same filesystem) so the rename is atomic. BEFORE the promote,
  explicitly DROP any open read/snapshot Connection/handle to `session.db_path` (Windows fails a
  replace while a handle is open) — the snapshot connections are already scoped/closed in
  dry_run_merge, but merge_commit must hold NO open handle to session.db_path at promote time.
  Then set `session.dirty = true`. Do NOT VACUUM/trim
  here — trim runs on the next Save via the existing path (D5-Discretion: no double-trim).
  Best-effort cleanup of the staging dir.

  MEDIA FOLD-BACK (Pitfall 2 / Open-Q1): after the successful staging merge and BEFORE deleting
  the staging dir, walk `staging/` for any file (excluding `userData.db*` and the `merge/`
  subdir) whose relative name is NOT already in `session.entries`. For each such new file: copy
  it into `session.temp_dir` at the same relative path AND push a `ZipEntryMeta{name}` into
  `session.entries` so `rebuild_zip` (save.rs:104) includes it. Structure this so that when
  jwlCore writes ONLY userData.db (the empirically-likely case per A1), the fold-back loop is a
  correct no-op. Add a doc comment recording what Task 3 observed empirically.
  Register `pub mod merge;` in `archive/mod.rs`.

| incoming source `.jwlibrary` → extractor | untrusted zip extracted into staging merge/ subdir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04 | Tampering | zip-slip path traversal in source archive | mitigate | extract_zip_slip_safe (Phase 1) for the merge/ subdir; never raw extractall |
| T-05-05 | Tampering/DoS | dry-run mutating the live session | mitigate | dry-run + commit ALWAYS run on a fs::copy / staging copy; session.db_path overwritten only on successful commit |
| T-05-06 | Data loss | merged media dropped by Save | mitigate | fold-back walks staging dir, adds new media to session.entries; empirically verified (Task 3) |
| T-05-07 | Tampering | concurrent merges clobber getLastResult / progress slot | mitigate | commands serialize under SessionState mutex; getLastResult read in same critical section (D5-06) |
