Purpose: despite the name "raw data viewer/editor", the Python surface is three fields for Notes and one for Annotations plus a single delete — modeling it as arbitrary SQL would invent a corruption vector the Python never had. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React frontend → Tauri command | Record field values and one record identity cross here as untrusted input |
| Tauri command → rusqlite | SQL construction boundary over irreplaceable user data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-24 | Elevation of Privilege | "raw editor" accepting arbitrary table/column/SQL | critical | mitigate | Typed payload with named optional fields only (D7-09); acceptance criterion greps the command signature for any table/column/sql parameter |
| T-07-25 | Tampering | annotation delete over-deleting silently | high | mitigate | Browse path is by-LocationId by design with an explicit preview override sentence; editor path is keyed by `(LocationId, TextTag)`; a test asserts the sibling row survives |
| T-07-26 | Tampering | record field values interpolated into SQL | high | mitigate | All values bound; only IN-clause placeholder COUNT dynamic |
| T-07-27 | Tampering | Bookmarks delete keyed on the wrong column | medium | mitigate | Identity PK taken from `browse.rs:33-37` (BookmarkId, not the first-SELECTed LocationId); test asserts only selected ids are removed |
| T-07-28 | Repudiation | double-fired delete from the editor | medium | mitigate | Routes through `EditPreviewDialog` and its `busyRef` guard |
| T-07-29 | Elevation of Privilege | mutation escaping the preview envelope | high | mitigate | `dry_run_record_edit` uses a never-committed `unchecked_transaction` under `PragmaGuard` |
| T-07-SC | Tampering | npm/cargo installs | high | mitigate | No new dependency planned; any install requires a blocking human legitimacy checkpoint |
</threat_model>

<schema_gate>
Schema-affecting: UPDATEs to `Note.Title`/`Content`/`LastModified`/`UserMarkId` and `InputField.Value`; INSERTs into `UserMark`; DELETEs from `Note`, `Bookmark`, and `InputField`. Constraint hazards: `InputField`'s composite natural key `(LocationId, TextTag)` (rowid table — `snapshot_pks(tx, "InputField", "rowid")` is valid only inside one dry-run transaction); `Bookmark UNIQUE(PublicationLocationId, Slot)`.
</schema_gate>
