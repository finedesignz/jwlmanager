<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-supplied `.jwlplaylist` zip → extractor | The phase's only new zip-open site: hostile entry names, absurd entry counts, malformed manifest |
| Mini-database contents → target archive SQL | Every value inside an imported container is untrusted, including its primary keys |
| Tauri command → filesystem | Temp extraction directories and media file copies into the archive working directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-24 | Elevation of Privilege | zip-slip via a hostile `.jwlplaylist` | high | mitigate | `extract_zip_slip_safe` is the only extraction path; a raw `ZipArchive` extract loop is prohibited and grep-verified |
| T-08-25 | Tampering | trusting an incoming primary key | high | mitigate | Semantic identity on `(Label, ThumbnailFilePath, Tag Name)` plus fresh gap-pool allocation; a collision test proves an existing row is never overwritten |
| T-08-26 | Tampering | SQL built from mini-database content | high | mitigate | All values bound via `params_from_iter`; only placeholder counts are dynamic |
| T-08-27 | Denial of Service | media copy failure leaving inconsistent state | high | mitigate | PD-3 ordering — DB staged, files copied, commit only on full file success; export-side copy failures are best-effort warnings that never abort |
| T-08-28 | Denial of Service | decompression bomb / absurd entry count | low | accept | No hard cap requested by any decision; extraction is bounded by the existing zip-slip guard and available disk. Accepted and documented |
| T-08-29 | Elevation of Privilege | mutation escaping the preview envelope | high | mitigate | `dry_run_import_playlist` uses a never-committed `unchecked_transaction` and writes no file into the archive working directory |
| T-08-SC | Tampering | cargo/npm installs | high | mitigate | No new dependency in this plan |
</threat_model>
