# Phase 8 Plan 4: Notes Export/Import + Semantic Round-Trip Summary

Ships Notes `.txt` export/import — the widest bracket-tag vocabulary of any category, the second `merge_range_into` call site (driven by the sequential multi-range `RANGE` attribute), and the conditional title-character bucket delete — then closes the five-category `.txt` set with `io_roundtrip_tests.rs`, a semantic round-trip suite asserting each category's REAL stability property.

## What was built

**`db/io/export.rs`** — `export_notes` ports `export_notes`'s txt branch plus the shared `get_notes` item-derivation that runs unconditionally before the format branch: per-shape (Bible / publication / independent) bracket ORDER exactly matching the documented spec, `TAGS`' `" | "`→`|` collapse, the HEADING auto-fill (`ResourceCatalog::bible_book`) and `":VS"`-append quirks, the always-omitted Bible-shape `BLOCK` bracket, `Reference` computation (`BK.zfill(2)+CH.zfill(3)+VS.zfill(3)`), and the `\n==={END}===` sentinel. A hand-authored `notes_golden.txt` fixture covers all three record shapes plus a tagged, multi-line, preset-HEADING Bible note and an untitled multi-line independent note — the exported bytes byte-match it exactly on the first run.

**`db/io/import.rs`** — `parse_notes_file` returns `(Option<char> bucket, Vec<NoteRecord>)`: the `{NOTES=(.?)}` tag capture ported exactly (0-or-1 character, never more), the Annotations-style `\n===`-boundary record scanner, first-newline title/note split, and every numeric attribute (including each `RANGE` sub-range) parsed to typed values at parse time (D8-04). `apply_import_notes(tx, bucket, records, available, guid_seed, now)`:
- `bucket: Some(c)` runs `DELETE FROM Note WHERE Title GLOB ?` (bound) BEFORE any record; `None` never deletes, regardless of what the file's own tag line named.
- Per record: resolves the scripture/publication/independent Location, synthesizes a fresh UserMark ONLY when `COLOR != 0` (`apply_note_usermark`), merges each `;`-separated RANGE sub-range SEQUENTIALLY through the SAME `db::io::usermark::merge_range_into` Highlights uses (D8-05 — a cross-category test proves a Notes RANGE merges into an existing Highlights BlockRange), then upserts the Note by `(LocationId, TRIM(Title), BlockIdentifier, BlockType)` or the untitled `(Title='', TRIM(Content), BlockType=0)` match, and re-processes its bare-`|`-split tag list.
- `dry_run_import_notes` follows the established never-committed-transaction shape over the new `NOTE_IMPORT_SNAPSHOT_TABLES`.

**`db/edit.rs`** — Adds `NOTE_IMPORT_SNAPSHOT_TABLES` (`Location`, `UserMark`, `BlockRange`, `Note`, `Tag`, `TagMap`).

**Tauri commands**: `export_notes` (threads a `ResourceCatalog` load like `list_category` does, for the HEADING auto-fill), `import_notes_dry_run` (returns the new `NotesImportPreview { report, bucket }` DTO — `bucket` is the FILE's own detected character, purely informational; the preview's `report` already reflects what WOULD happen if that bucket were applied, since a dry run always rolls back), `import_notes_apply` (takes its own `bucket: Option<String>` argument from the frontend, decoupled from the file).

**Frontend**: `operations.ts` flips `Notes:export`/`Notes:import` LIVE. `CategoryList.tsx` adds Notes to `EXPORT_COMMANDS`/`IMPORT_COMMANDS`, special-cases the Notes dry-run response shape, and renders the Notes-only bucket-delete opt-in checkbox (rendered from `report.deleted`, per D8-09) inside the shared `EditPreviewDialog`'s `summary` slot — the confirm handler only ever sends `bucket` when that checkbox was explicitly checked.

**`io_roundtrip_tests.rs`** (new) — one test per category driving export→reimport→export against a seeded `fresh_v16_db()`: Favorites/Bookmarks/Annotations/Notes assert unchanged `normalized_table_rows` (no duplication) AND byte-identical second-export bytes; Highlights asserts `BlockRange` geometry convergence alongside the accepted `UserMark` growth. Plus an ID-recycling assertion and a cross-category smoke test proving all five share one spine without interference.

## Deviations from Plan

None — plan executed as written. The `NotesImportPreview` DTO (a small addition beyond the plan's literal `files_modified` list, which only named the three Tauri commands) was needed to let the dry-run preview surface the file's own bucket character to the frontend without inventing a second IPC round-trip; this is the natural, minimal shape for D8-09's "surfaced honestly, applied only on opt-in" requirement and required no `db/edit.rs` `DryRunReport` struct change (the existing `report.deleted` map already carries the honest count once the dry-run is passed the file's real bucket).
