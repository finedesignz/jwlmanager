<phase_decisions>
Three decisions the orchestrator required this planner to resolve explicitly. Recorded here once, binding on every plan in this phase.

**PD-1 — the `image` crate: NOT added. Ship the no-resize thumbnail (RESEARCH addendum option (b)).**
The mandatory live legitimacy check could not be run (network paths blocked; RESEARCH `⚠ Addendum`), so the crate cannot be blessed, and a `checkpoint:human-verify` that no session in this environment can satisfy would block the phase's critical path on an unsatisfiable gate. The project has added zero new Cargo dependencies in seven phases. A thumbnail is structurally required (`PlaylistItem.ThumbnailFilePath` + a second `IndependentMedia` row); the 250x250 *resize* is not. Plan 08-06 therefore copies the source image bytes unmodified to the thumbnail path, producing a valid, JW-Library-readable archive that diverges from Python on file SIZE only — never on schema, wire format, row count, or hash correctness. Recorded as a deliberate, documented deviation with a source TODO citing the addendum. Reversibility: **reversible** — adding real resizing later is a purely additive change behind the same function boundary, with no on-disk or wire-format migration.

**PD-2 — `DryRunReport` gains a real `skipped` field.** The UI-SPEC's ⚠ unresolved row is resolved in favour of the higher-fidelity shape: `pub skipped: BTreeMap<String, usize>` added to `db/edit.rs::DryRunReport`. It is `Default`-derived, so every existing constructor (`diff_snapshots` and every Phase 2/7 op) keeps compiling and reports an empty map — no existing consumer changes semantics. Only the import paths populate it. Folding skips into `overwritten` was rejected: a Favorites string-level dup skip performs ZERO writes, and reporting it as an "update" would tell the user the archive changed when it did not — a Core-Value-adjacent lie in the one dialog whose whole job is telling the truth about what will change. Reversibility: **reversible**.

**PD-3 — media write vs. DB commit ordering: RESEARCH's inversion CONFIRMED, per direction.**
*Add* (08-06): open the transaction, stage every DB insert, copy/write every file, and commit ONLY if every file write succeeded; any file-write failure rolls back the transaction. Rationale: a file with no DB row is a cleanable orphan; a committed row pointing at a missing file is corruption the user discovers only when JW Library fails to render.
*Delete* (08-06): commit the DB deletion FIRST, then best-effort `std::fs::remove_file`, ignoring a missing-file error exactly as Python does (D8-07) — the DB row is authoritative, and a leftover file is again a cleanable orphan.
Both directions therefore fail toward "file exists that the DB does not know about," never toward "DB references a file that is not there." Dry-run never reaches either code path. Reversibility of the *delete* direction: **one-way** — `remove_file` destroys user media outside SQLite's rollback guarantee, so plan 08-06 carries a `checkpoint:decision` immediately before the task that implements it.
</phase_decisions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-supplied `.txt` file → parser | The core new surface: untrusted external content, not archive-resident data |
| React frontend → Tauri command | Resolved file paths and optional selection ids cross here |
| Tauri command → rusqlite | SQL construction boundary; the archive is irreplaceable user data |
| Tauri command → filesystem (export write) | A user-chosen destination path is written to |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | `db/io/import.rs` parser | high | mitigate | Field count validated to exactly 6 before any SQL runs; a short/long line is a typed `ImportMalformed`, never an indexed panic |
| T-08-02 | Tampering | import SQL | high | mitigate | Every parsed field bound via `params_from_iter`; no parsed content ever reaches SQL text |
| T-08-03 | Tampering | `db/ids.rs` dynamic table name | medium | mitigate | Table names drawn only from the internal `RECYCLING_TABLES` const — never from a caller, frontend, or parsed file |
| T-08-04 | Elevation of Privilege | mutation escaping the preview envelope | high | mitigate | `dry_run_*` uses a never-committed `unchecked_transaction` under `PragmaGuard`; only `*_apply` commits |
| T-08-05 | Denial of Service | archive integrity under FK-off | high | mitigate | `PragmaGuard` wraps every FK-off region (PRAGMAs survive rollback) |
| T-08-06 | Repudiation | double-fired apply | medium | mitigate | `EditPreviewDialog`'s synchronous `busyRef` guard is reused unchanged |
| T-08-07 | Denial of Service | oversized/malicious import file | low | accept | No hard size cap is requested by any decision; parsing is single-pass and bounded by file size. Accepted, documented, revisit only on a real report |
| T-08-08 | Information Disclosure | export writing to an unintended path | low | mitigate | The path comes from the OS save dialog, not from parsed content; a write failure is a typed `ExportFailed` stating the archive is unchanged |
