Implement `pub fn save_v14_copy(session: &ArchiveSession, target: &Path, app_name: &str, device_name: &str, now_iso8601: &str) -> Result<(), ArchiveError>`:

1. Materialize a throwaway copy: create a temp file inside `session.temp_dir` (e.g. `userData_v14.db`) via `std::fs::copy(&session.db_path, &copy_path)` (research: file-copy, matches Python `shutil.copy2`; ensure no pending WAL — the working copy is opened per-operation and closed, so it is clean). NEVER copy over or mutate `session.db_path`.
2. Open the COPY, `trim_db(&mut conn)` then `downgrade_to_v14(&mut conn)` (trim-before-downgrade order, on the copy only), close the connection.
3. Write the v14 archive to `target` through the atomic-save path. The cleanest reuse: build a save that uses the COPY as the userData.db source instead of `session.db_path`. Either (a) add a small internal variant of `save_archive_to`/`rebuild_zip` parameterized on the db-bytes source path, OR (b) temporarily point rebuild at `copy_path` — pick the minimal-diff option and document it. Every non-userData.db entry still streams from `session.temp_dir` unchanged (loose media, thumbnails). The output manifest's schema_version reads the COPY's PRAGMA (=14). Use the existing `same_dir_temp + atomic_replace` guarantee — never delete-then-rename.
4. Delete the throwaway copy on the way out (best-effort; it lives in the session temp_dir which is cleaned on session drop anyway).
5. Return `Ok(())`. Any failure → typed ArchiveError, `target` untouched (atomic-save invariant), session untouched.

Do NOT set `session.dirty` or change `session.target_path` — a v14 copy is a side export, not the session's save target (D4-07).
