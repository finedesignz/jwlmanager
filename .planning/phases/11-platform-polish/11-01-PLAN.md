<scope_boundary>
Settled during planning; do not re-derive or re-litigate. This is the terminal
phase of the milestone and every prior phase left a "-> Phase 11" note here.

**In 1.0 (this phase, the three literal ROADMAP criteria only):** Windows
signing WIRING (plan 11-02), a dependency-free i18n layer with English complete
(plans 11-03/11-04), light+dark theme switching (this plan), and the two-key
persisted settings surface that makes those two switches durable (this plan).
A minimal About surface is included because it is the natural host for the two
switchers and costs almost nothing.

**Explicitly follow-up milestone, NOT 1.0 -- do not re-absorb:** real
translations for the other eight locales (no translator resource exists; see
plan 11-03), auto-update pipeline (tauri-plugin-updater + update server + key
distribution), macOS notarization (needs an Apple Developer credential this
environment does not have), custom brand icon/logo redesign, persisted window
geometry / last-selected category / sort-column, grouping and tree hierarchy,
title-view modes, and the duplicate-notes CTE filter. Several of these were
informally called "Phase 11" by earlier CONTEXT files but appear in none of the
three ROADMAP success criteria.

**Settings shape is exactly two keys.** `{ language, theme }`. Adding a third
key is out of scope for this phase even though the file format trivially allows
it (D11-04).

**Load/save asymmetry is intentional.** `load_settings` returns a plain
`AppSettings` and never a Result, because a brand-new user with no settings file
is not in an error state and must not see a banner on first launch.
`save_settings` DOES return a typed Result, because a failed save silently
discarding the user's choice is worth surfacing. A reviewer should read this as
a deliberate, documented deviation from the project's `Result<T, ErrorDto>`
convention, not as drift.

**First-frame theme flash is accepted (RESEARCH Pitfall 2, CONTEXT Claude's
Discretion).** The persisted value lives in a Rust-owned file, so it cannot be
read synchronously before React paints. A user with a saved light preference may
see one frame of dark. The sanctioned alternative -- mirroring settings into
localStorage so an inline bootstrap script can read them synchronously -- adds a
second write path for a cosmetic gain and is rejected.
</scope_boundary>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS filesystem -> backend | `settings.json` under the app-data directory is untrusted input on every read; any local process or a hand-editing user can put arbitrary bytes there |
| frontend -> backend | the save command accepts an `AppSettings` deserialized from IPC; `theme` is a closed enum, `language` is a free String |
| settings domain -> archive domain | the boundary that must NOT be crossed: settings code has no path into ArchiveSession or the archive save path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Denial of service | `load_settings` reading a crafted or corrupt settings file | medium | mitigate | Every read/parse failure is absorbed into `AppSettings::default()`; no propagation, no panic, no startup block. Proven by `settings_corrupt_file_returns_defaults` and `settings_truncated_file_returns_defaults` |
| T-11-02 | Tampering | settings write leaking into or corrupting the user's archive (Core Value) | high | mitigate | The settings path is derived exclusively from Tauri's app-data directory, never from a user-chosen path; the module names no archive or session type, asserted by the structural test in task 2 |
| T-11-03 | Elevation / path traversal | a `language` value used to build a filesystem path | medium | mitigate | `language` is never used to build a path, query, or command -- it is only an in-memory lookup key into a TypeScript record, which returns undefined and falls back to English for any unrecognized value (see plan 11-03) |
| T-11-04 | Tampering | an unexpected `theme` value from a hand-edited file | low | mitigate | `Theme` is a closed enum; an unrecognized value fails deserialization, which lands in the same degrade-to-defaults path as any other parse failure |
| T-11-05 | Information disclosure | settings error detail reaching the UI | low | mitigate | Load never returns an error at all; save returns the project's sanitized DTO shape, which already never leaks internal paths (D-14) |
| T-11-SC | Tampering | Cargo / npm dependency supply chain | low | accept | Zero new dependencies -- `app_data_dir` is core Tauri Manager API and `serde_json`/`thiserror`/`ts-rs` are already present. RESEARCH's Package Legitimacy Audit is N/A. A dependency that seems unavoidable is a BLOCKING checkpoint, not an executor decision |
</threat_model>
