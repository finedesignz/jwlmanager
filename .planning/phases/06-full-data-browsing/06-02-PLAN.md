Follow the `query_located_notes` mapping pattern in `notes.rs` (a raw-row struct → label synthesis → BrowseRow).

Port exactly, filling the BrowseRow subset each category produces and defaulting the rest to None/absent (per the 06-RESEARCH per-category surfaced-columns table):
- query_annotations — `JWLManager.py:643`. SQL selects LocationId, l.KeySymbol, l.MepsLanguage, l.IssueTagNumber, TextTag, l.BookNumber, l.ChapterNumber, l.Title FROM InputField JOIN Location l USING (LocationId). Identity = LocationId (`row.id` = LocationId). Runs lang_name + process_code + process_detail(book, chapter) + resolve_publication + the `"* NO YEAR *"` year fallback. color/tags/modified = None. symbol = code, or `"* OTHER *"` when the processed code is empty.
- query_bookmarks — `JWLManager.py:656`. SQL: LocationId, l.KeySymbol, l.MepsLanguage, l.IssueTagNumber, BookmarkId, l.BookNumber, l.ChapterNumber, l.Title FROM Bookmark b JOIN Location l USING (LocationId). Identity = BookmarkId (`row.id` = BookmarkId, NOT LocationId — this is the pitfall). Same label synthesis as Annotations.
- query_favorites — `JWLManager.py:669`. SQL: LocationId, l.KeySymbol, l.MepsLanguage, l.IssueTagNumber, TagMapId FROM TagMap tm JOIN Location l USING (LocationId) WHERE tm.NoteId IS NULL ORDER BY tm.Position. Identity = TagMapId. process_detail called with book=None, chapter=None. Keep the `WHERE tm.NoteId IS NULL ORDER BY tm.Position` exactly — a Favorite is a TagMap row with NULL NoteId; dropping the predicate lists note-tag mappings as favorites.
- query_highlights — `JWLManager.py:682`. SQL: LocationId, l.KeySymbol, l.MepsLanguage, l.IssueTagNumber, b.BlockRangeId, u.UserMarkId, u.ColorIndex, l.BookNumber, l.ChapterNumber FROM UserMark u JOIN Location l USING (LocationId), BlockRange b USING (UserMarkId). Identity = BlockRangeId. One row PER BlockRange — do NOT GROUP BY it away (a multi-block highlight is intentionally multiple selectable rows). color = Some(process_color(ColorIndex)) — Highlights is the only new category carrying color.
- query_playlists — `JWLManager.py:770`. SQL: PlaylistItemId, Name, Position, Label FROM PlaylistItem JOIN TagMap USING (PlaylistItemId) JOIN Tag t USING (TagId) WHERE t.Type = 2 ORDER BY Name, Position. Identity = PlaylistItemId. Per D6-04 Playlists needs NO resources.db lookup and does NOT call process_code/process_detail: set language=None, symbol=`"* OTHER *"`, tags=Some(Name), detail1=Some(Label), year per the Python (`''`), short/full=`"* OTHER *"`, type_group=`"Other"`. The `catalog` param is still accepted (uniform signature) but unused — allow the unused binding, do not special-case the call site.

Only publication names/refs (metadata via ResourceCatalog) are read — never publication body text (project constraint). No `.unwrap()`/`.expect()` anywhere in `browse.rs` (crate deny gate); use `?`/`unwrap_or` defaults exactly as `notes.rs` does.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-03 | Tampering | SQL injection via category dispatch | high | mitigate | `Category` is a Rust enum over IPC (unknown values fail deserialization); the five getter SQLs are static `const &str` with zero interpolation; the only bound value in the browse path is resources.db `ui_lang_id`, already parameterized in `resources.rs`. |
| T-06-04 | Denial of Service | malformed archive rows crash a getter | medium | mitigate | Typed `ArchiveError` + `?`; nullable columns read via `Option` with `unwrap_or` defaults; no `.unwrap()`/`.expect()` on the archive-data path (crate deny gate). |
| T-06-05 | Information Disclosure | surfacing publication body text | high | mitigate | Getters read only names/refs from resources.db metadata via `ResourceCatalog`; no query touches publication body content. |
| T-06-SC | Tampering | npm/cargo dependency installs | high | accept | Phase 6 adds no package (06-RESEARCH audit N/A); verify `Cargo.toml`/`package.json` unchanged. |
