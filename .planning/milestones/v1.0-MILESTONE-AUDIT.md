## 5. Core Value: Never Lose or Corrupt a User's Archive

This is the standard everything else is subordinate to. Findings, checked directly against code:

- **Save path is atomic:** same-directory temp file write, `sync_all`, then `fs::rename` — no delete-then-rename window (`save.rs`, confirmed by code read + `save_failure_before_replace_leaves_original_target_intact` test).
- **Manifest hash is last-step, computed on final on-disk bytes** (not pre-VACUUM in-memory state) — matches the Python app's ordering exactly.
- **Merge/fold sources are read-only.** Both the two-archive merge (Phase 5) and the fold (Phase 10) prove this with pre/post file-hash equality checks across a forced mid-operation failure, not just an assertion of intent.
- **Atomic promote is single and outside the operation loop** for both merge and fold — confirmed by direct code reading of the call site (`merge.rs:624` for fold), not a claim taken on faith. No partial-merge state is ever visible to the live working copy.
- **All SQL is parameterized.** Grepped every `format!()` that produces SQL, in every phase's modified files: matches are exclusively placeholder-count strings or static internal table/column-name constants — never a user-supplied value. Zero string-interpolated SQL values found anywhere in `src/`.
- **Zip-slip protection is the sole extraction path** for every untrusted-zip boundary found across all 11 phases (initial archive open, playlist-container import) — six fixture variants tested (relative traversal, absolute path, symlink chain, backslash traversal, duplicate entries).
- **Every mutating operation is dry-run-previewable and runs in a non-committed transaction for preview, a real transaction for apply** — the dry-run/apply pattern established in Phase 2 (SAFE-01/03/04) was never violated by any later phase; confirmed structurally via the command-registration cross-check in section 3, not by trusting each phase's narrative.
- **Errors are typed and cross the IPC boundary without raw paths** (`ErrorDto`, `safe_file_name` field) — the Python app's bare `except: pass` / crash-and-exit pattern was deliberately not ported anywhere.
- **Empty-selection mutations are impossible by construction** — every dry-run/apply command pair for a selection-based op takes a typed non-empty-ID collection (`NonEmptyNoteIds`, `NonEmptyTagMapIds`, `NonEmptyBlockRangeIds`, etc.), not a button-state guard alone.

**No path was found in this audit where a save, merge, fold, import, or edit operation could silently lose or corrupt data.** The one honestly-documented functional gap (pairwise-merge playlist-table assertion, section 6) is a coverage gap in the test proving playlist rows survive a **2-archive** merge — not a known-bad code path; the same merge machinery is exercised successfully with a full playlist graph at the fold level (≥3 archives) in Phase 10, and the underlying merge call is jwlCore itself (the same sanctioned engine the Python app uses), so there's no reason to believe the 2-archive case behaves differently — it's simply unasserted for that exact fixture shape.

## 6. Parity with the Python App

Genuinely reached, verified by direct comparison, not merely claimed:

- Manifest field order, compact JSON separators, `'None'` sentinel, `|`→`¦` escaping, `==={END}===` export sentinel, UTF-8 header forcing — all ported and round-trip tested against files the Python app format expects.
- `trim_db` orphan sweep + tag re-densify + VACUUM ported "in verbatim statement order" from `JWLManager.py:3858-3935`.
- Two-pass negative-position reorder technique: **not** ported literally — replaced with a documented, tested, provably-equivalent TEMP-table staging technique (Phase 7, D7-05). This is a deliberate, reasoned substitution with an adversarial max-collision fixture proving equivalence, not an unproven claim.
- Highlight recolor union-merge: Phase 7 found and correctly resolved a real discrepancy between the ROADMAP's stated criterion and the Python app's actual behavior (Python's `set_color` does NOT union-merge on recolor; only its import path does) — documented as D7-03, resolved as strict parity to the Python app's real behavior rather than the ROADMAP's imprecise wording. This is parity **correctly reached to the actual reference implementation**, catching what would otherwise have been a false "improvement" that broke parity.
- ID-gap recycling on import ported and tested (IO-03).
- Schema downgrade's 7-table LocationId remap closure ported with documented, tested ordering semantics (SCHEMA-04).

One area of unproven (not false, just unverified-here) parity: **actual byte/behavioral acceptance by the real Python app and real JW Library**, gated behind environment/proprietary-app limitations acknowledged at Phase 1 and never independently re-closed later. The `differential.rs::python_app_opens_tauri_saved_archive` Python-oracle test exists and is loudly `#[ignore]`d for this exact reason across multiple phases — this is the standing, always-known limitation, not new information from this audit.
