# Milestone v1.0: JWL Manager (Tauri) — MVP Parity + New Value

**Status:** ✅ SHIPPED 2026-08-16
**Phases:** 1-11
**Total Plans:** 45

## Overview

From-scratch Tauri (Rust core + React/TS frontend) rewrite of the PySide6 `JWLManager.py` desktop app for managing `.jwlibrary` backup archives. Built as 11 vertical MVP slices, reaching full functional parity with the Python app (open/view/edit/delete/import/export/merge across all 6 data categories, schema upgrade/downgrade, localization, theming) while adding new value the Python app never had: dry-run previews before every destructive operation, incremental export, N-way merge fold, and Windows code-signing wiring.

Core value guardrail held throughout: never lose or corrupt a user's archive. Every destructive operation ships with a dry-run preview, transactional rollback, and a round-trip semantic-equivalence test — never byte-diffing.

## Milestone Summary

**Key Decisions:**

- Tauri rewrite over incremental Python fixes — owner's call, made against a RESHAPE council verdict, accepting the parity risk knowingly.
- Bind `jwlCore` via `libloading`; never reimplement merge — the hardest logic reuses the existing hash-verified prebuilt binary.
- Test as we go, per-phase, in the new app — no retrofitted characterization harness; parity oracle is per-phase differential testing against the Python app.
- Vertical MVP slices — every phase ships an end-to-end working capability, avoiding "months of no value."
- Dry-run diff prioritized early (Phase 2) — every later destructive operation (downgrade, merge, fold) reuses the same DryRunReport mechanism.
- Stable category enums replace translated-string control flow (`if category == _('Notes')`) — fixes a latent i18n bug at the root.
- MERGE-03 (N-way fold) and IO-04 (incremental export) split into their own phases rather than bundled into parity phases.
- Zero new runtime dependencies held across all 11 phases (jwlCore binding, wire-format serialization, i18n catalog all hand-rolled against existing primitives).

**Issues Resolved:**

- jwlcore.py's OS-only native-binary selection bug fixed with arch-aware (OS, ARCH) selection (Phase 1).
- Python's silent `except: pass` schema-upgrade failure mode replaced with a transactional, rollback-on-failure port (Phase 3).
- D10-06 playlist-graph merge gap (documented tech debt from Phase 5's pairwise merge) closed at the fold level in Phase 10 against the real jwlCore DLL.
- W-06-ANNOT-SYMBOL one-line fidelity deviation documented and confirmed non-blocking (Phase 6).

**Issues Deferred:**

- Real Windows Authenticode signature verification remains a manual step, blocked on Azure Trusted Signing credentials not provisioned in this environment (Phase 11); the wiring itself is complete and fails closed.
- Manual live-app verification of Phase 11 UX flows (settings, theme flip, restart, corrupt-settings recovery) deferred to operational follow-up; automated tests cover the same behaviors at the Rust/React layers.

**Technical Debt Incurred:**

- None carried forward uncharacterized — the one open item at Phase 5 (pairwise merge lacking its own playlist-graph assertion) was explicitly closed at the fold level in Phase 10, not silently left open.
